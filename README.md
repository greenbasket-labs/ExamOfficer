# ExamOfficer

ExamOfficer is an offline-first school examination and marks-management application being developed for schools that want to reduce repetitive manual work.

The initial product is designed around one central idea: **each student has one reliable record, and marks or other school information can be attached to that record through different workflows.**

## Product direction

- Local school profile, classes, sections, subjects, and student records.
- Unique student IDs, either supplied by the school or generated by the application.
- Manual mark entry and automatic marking of objective questions using a teacher-defined answer key.
- Import and scan workflows that help match marks to the correct student, subject, and assessment. Uncertain matches must be reviewed rather than silently accepted.
- Optional assessment labels such as CA1, CA2, or examination, while keeping mark collection flexible.
- Configurable grading and aggregation rules, attendance, and printable report cards.
- One-action backup that produces a readable PDF and a structured backup that can restore the data.
- Offline use without a required Gmail account or cloud account, with optional PIN protection.
- Windows-first validation followed by Android support and device-specific testing.

## Current implementation status

The repository currently contains the foundation for school profile storage, local SQLite persistence, classes, school sections, subjects, class-subject assignments, and student registration.

**The complete product described above is not yet implemented.** Objective marking, scanning/OCR, attendance, mark reconciliation, grading, report cards, backup/restore, PIN protection, and Android packaging must be developed and tested before they can be advertised as available features.

## Development

Prerequisites and platform-specific Tauri setup may be required.

Install frontend dependencies:

```powershell
npm install
```

Check the frontend build:

```powershell
npm run build
```

Run the desktop development application:

```powershell
npm run tauri dev
```

These are instructions, not a claim that the current checkout has passed the commands. Native builds also require the appropriate Rust toolchain and Tauri platform dependencies. Android builds require Android development tooling and additional platform validation.

## Data and privacy principles

The intended default is local storage on the school's device. The application should not transmit student records to a developer-controlled server. Backups can contain sensitive student information, so users should store and share them carefully. A local PIN is an access barrier, not a substitute for operating-system security or encrypted backups.

## Release status

ExamOfficer is under active development. Do not treat the repository as a production-ready examination system until the roadmap's data-integrity, backup/restore, calculation, platform, and usability checks have been completed.
